# Brackets

The current repository champion is [`p5v2.man`](p5v2.man), generated by
[`p5_build.py`](p5_build.py). It is a three-man streaming pipeline packed into a
17×17 footprint:

```text
input → C: classify → M: match with stack → P: count/emit → output
```

`C`, `M`, and `P` are the names used in the builder:

- **C (classifier)** consumes the length-prefixed input, classifies each ASCII
  bracket, and sends a compact signed token.
- **M (matcher)** stores the opener stack in one register, checks closers, and
  reduces the result to a small stream protocol.
- **P (position counter)** counts successfully accepted characters and converts
  M's verdict into the required output position.

The split is important because a pipe receive overwrites `A`, while the matching
stack must survive across receives. Separate rooms give each stage its own
registers, and blocking `r`/`s` instructions synchronize the stages without an
explicit scheduler.

## Problem

The input is `n` followed by `n` ASCII codes from:

| Character | ASCII |
| --- | ---: |
| `(` / `)` | 40 / 41 |
| `[` / `]` | 91 / 93 |
| `{` / `}` | 123 / 125 |

The output is `0` for a balanced string, the 1-based position of the first
offending closer, or `n + 1` if the input ends with unclosed openers. The
constraints are `n ≤ 64` and nesting depth `≤ 32`.

## Stream protocol

C maps each character to a signed type:

| C → M token | Meaning |
| ---: | --- |
| `+1`, `+2`, `+3` | opening parenthesis, square bracket, or brace |
| `-1`, `-2`, `-3` | corresponding closer |
| `0` | end of the current string |

For every character accepted before an error, M sends a positive trigger
(specifically `1`) to P. At the end M sends one verdict:

| M → P token | Meaning |
| ---: | --- |
| positive | one character was accepted; increment the position |
| `0` | balanced; emit `0` |
| negative (`-2`) | emit the accepted-character count plus one |

This makes one negative verdict cover both error cases:

- On an offending closer at position `i`, M has sent `i - 1` triggers, so P
  emits `i`.
- On unclosed openers after `n` valid characters, M has sent `n` triggers, so P
  emits `n + 1`.

Positions therefore never travel through the first two pipes. That removes the
reader/position stage used by the older solutions and is the main conceptual
simplification behind the `p3`–`p5` series.

## C: reader and classifier

C first receives and discards the length. It does not maintain a countdown.
Instead, `q` checks whether the input pipe still contains a value before each
iteration. The classifier loop is slower than input injection, so the pipe stays
non-empty while characters remain. Once the final character has been consumed,
`q == 0` selects the end path and C sends the `0` sentinel.

This also handles the empty string without a special read: after consuming
`n = 0`, the first `q` immediately selects the sentinel path. In multi-round
tests, the next round's input is withheld until the current output is emitted,
so it cannot make the current round's `q` nonzero.

The type magnitude is especially cheap:

```text
t = ASCII >> 5

40, 41   → 1
91, 93   → 2
123, 125 → 3
```

The opener/closer decision uses the low two bits through `b`, `x`, and `]`:

```text
ASCII even                         → opener       # only '('
ASCII odd and (ASCII >> 1) odd    → opener       # '[' or '{'
ASCII odd and (ASCII >> 1) even   → closer       # ')', ']', or '}'
```

An opener sends `+t`; a closer negates it and sends `-t`. This avoids a table,
large literals, or a multiply-based classifier.

## M: packed base-3 stack

M keeps the entire opener stack in register `B` as a base-3-like integer with
the noncanonical digits `1`, `2`, and `3`:

```text
S = 0                                      # empty stack
push(t):       S = 3*S + t
match/pop(t): require S != 0
              require (S - t) divisible by 3
              S = (S - t) / 3
```

The bracket types are already `1`, `2`, and `3`, so the signed C token contains
everything M needs to select push, pop, or end with an `X` branch. A positive
token pushes its magnitude and sends one trigger to P. For a negative token, M
subtracts its magnitude before dividing by three; a nonzero remainder identifies
a type mismatch. An empty stack or mismatch enters the offense path.

Depth 32 is safe in signed 64-bit arithmetic: the largest packed value is well
below `2^63`.

When C sends `0`, M checks whether `S` is empty. Empty produces verdict `0`;
non-empty produces the negative verdict that P turns into `n + 1`.

After an early offense, C has no feedback path and continues classifying the
remaining input. M therefore drains and discards tokens through the end
sentinel before sending its negative verdict. This leaves the C → M pipe empty
and all three stages in a clean state for the next round.

## P: position and output

P's `B` register is the accepted-character count. Its compact three-way loop
receives one M token at a time:

- positive: increment `B` and return to `r`;
- zero: send `0` to the output;
- negative: add one to the count and send it.

After emitting a result, P resets and waits for the next round. This stage is a
6×8 outer room with a 4×6 instruction interior in `p5v2`; reshaping it from the
earlier 7×9 form shortened its positive-trigger loop from 10 ticks to 8.

## Layout

The final 17×17 arrangement is intentionally square because the score uses
`max(width, height)²`:

- M is an 11×11 room in the upper-left. Its hot loops fit in a 9×9 interior.
- P is flush against M's east side.
- C is a 12×6 room below M and east-aligned with it.
- The output room is tucked below P in the gap above C.
- The input room sits immediately west of C.
- The C → M pipe bends tightly around M's southwest corner; the other pipes are
  similarly kept to one- or two-cell gaps.

Rooms may touch, but they do not share wall cells. Short pipes matter twice:
they reduce both footprint and transport latency.

`p5v2`'s final fold shrank M from 12×11 to 11×11. The drain loop moved to the
rightmost two interior columns, the send-1 path moved to the adjacent column,
and a `W` swap was moved onto the entry row. This reduced the scored box from
18² to 17² while also lowering average public ticks from 270.1 to 263.0.

## Results

The committed validation record for `p5v2` (`0189f41`) is:

- footprint: 17×17, box factor 289;
- public cases: 9/9;
- average public ticks: 263.0;
- local public score: `289 × 263 = 76,007`;
- additional fuzz cases: 340 passed.

The nine public cases were also rechecked with the repository's Rust parity
interpreter while writing this document, including the empty string, early
offenses, deep nesting, and the full-length case.

These are local results. The last variant with a server result recorded in git
is `p4v1.man`: 26/26 cases and score 191,343.88. The later `p5v1` and `p5v2`
commits record public and fuzz validation but no server score, so do not present
76,007 as a server score without checking the live submission dashboard.

## Rebuild and verify

Generate a fresh copy without overwriting the checked-in champion:

```bash
python3 solutions/brackets/p5_build.py /tmp/brackets-p5v2.man
cmp solutions/brackets/p5v2.man /tmp/brackets-p5v2.man
```

Grade with the organizer WASM oracle after running `sim/fetch-oracle.sh`:

```bash
node tools/grade.js brackets solutions/brackets/p5v2.man
```

For a quick single-case check with the Rust interpreter:

```bash
cargo run --quiet --manifest-path interp/Cargo.toml --bin lm -- \
  --grade solutions/brackets/p5v2.man \
  '--input=4 40 91 41 93' '--expected=3'
```

## Evolution

The useful milestones are:

| Variant | Main change | Box / recorded result |
| --- | --- | --- |
| `stack2` | Original reader → classifier → matcher pipeline | 36×47, server 26/26 |
| `stack4` | Bit-based classifier | 33×33-era layout, 969,172 server |
| `stack5` | Narrow hot loops | 31×31, 556,640 server |
| `stack6` | Pure layout fold | 23×23 |
| `p3` | Three-stage signed-token protocol; positions removed from pipes | 20×20-era layouts |
| `p4v1` | Tighter packing around M | 19×19, 191,343.88 server |
| `p5v1` | Smaller P; C and output repacked | 18×17 |
| `p5v2` | M folded to 11×11 | **17×17, 76,007 local** |

Keep the older `.man` files: they document working intermediate designs and
provide regression points when changing the builder.
